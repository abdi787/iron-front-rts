Critical Invariants (DO NOT BREAK):
- Render cadence: ANIM_FPS = 20, ANGLE_STOPS = 32 (11.25 deg step) in js/renderer3d.js.
- Zoom-invariant pixel resolution: PIXEL_WORLD = 1.0 in js/renderer3d.js. FBO dimensions & world origin (wx0, wy0) lock to integer world units; renderer.js draws scene.canvas in world coordinates (scene.x, scene.y, scene.w, scene.h) with imageSmoothingEnabled=false. Never couple pixelWorld to cam.zoom or viewport width.
- Orthogonal buildings: Building facingDir is 0..3 (0, 90, 180, 270 deg; facingRad = facingDir * PI/2). Never hardcode diagonal base rotation. Units exit motorpool/depot along facingRad.
- HQ-Only Match Start: startNewGame() spawns only hq (0 units) for both player and AI; AI expands via depot -> motorpool -> generator -> bunkers.
- Depot & Per-Building Production: hq neither accepts supply dropoffs nor builds harvesters. Only depot accepts supplies and builds harvesters (plus spawns 1 free harvester upon build completion); only motorpool builds combat units. #unitDock is context-sensitive to the selected depot/motorpool and calls queueUnit(faction, kind, prod.id).
- C&C Power Rules: recomputePower() counts both powerProduced and powerConsumed ONLY for completed living buildings (buildProgress >= 1). Construction continues during low power. On isLowPower(), motorpool queues pause, bunker/heavyGun turrets stop firing, workshop stops healing, command radar stops & artilleryBarrage locks ("Нет ⚡"), while hq/generator/depot (dropoff + harvester queue) stay active to prevent softlocks.
- Kill-Based Veterancy: Ranks 0..3 unlock at 0/1/2/3 last-hit kills of enemy combat units (buildings & harvesters excluded).
- Progressive Supply Piles: buildPropMeshes() outputs { base, items[6] } per variant so crates/drums vanish step-by-step from the full-sized pallet instead of scaling down.
- Building Tech Tree & Power Gating: Without a completed depot, only generator and depot can be built; motorpool/bunker/workshop require depot; command requires motorpool (and depot); heavyGun requires command. Only once the grid is actually in Low Power (isLowPower: completed powerConsumed > powerProduced, matching the HUD gauge) are energy-dependent buildings (powerDelta < 0) blocked until generators restore power; buildings still under construction do not pre-lock cards.
- World Status Bars & Badges (renderer.js + renderer3d.js): Construction/unit-queue/spawn horizontal progress bars render directly BENEATH buildings (bBot) and units (uBot); building repair shows ONLY the HP bar + spinning 3D pixel-art wrench icon above (no duplicate bottom repair bar). Placement ghosts visualize rectangular AABB clearance boundaries (getBuildingClearanceRect / getPropClearanceRect / rectsOverlap in sim.js + renderer.js) + base build radius + failure reason.
- Dynamic Multi-Map & Relative AI: Never hardcode WORLD_WIDTH/WORLD_HEIGHT (2400x1600) or SW/NE coordinates inside gameplay/render loops. Always read sim.worldW/sim.worldH, sim.playerSpawn/enemySpawn, and sim.currentMap. Enemy AI placement in updateEnemyAi() expands relative to its HQ & nearest supply cluster with spiral fallback.

3. 3D-to-Pixel Art Pipeline Mechanics

Vertex Format & Coordinate Convention

  • Interleaved buffer (MeshBuilder): 12 float32 values (48 bytes) per vertex: [x, y, z, nx, ny, nz, r, g, b, emissive, matId, vAo].
  • matId shader switches (ENTITY_FRAG): 0 armor/concrete micro-grain; 1 ribbed tracks/rubber; 2 yellow/dark hazard stripes; 3 segmented carapace/terrain; 4 glossy glass/emissive high-specularity metal.
  • Top-down oblique orthographic projection (ENTITY_VERT): 
    sx = (uEntityPos.x + ox) - uCamPos.x
sy = (uEntityPos.y - uCamPos.y) + oy * 0.68 - oz * 0.73
    Ground depth foreshortens along Y by 0.68 while vertical height Z shifts UP by -0.73. During uShadowPass > 0.5, vertices shear across the ground plane via ox += oz * 0.72; oy -= oz * 0.36; oz = 0.0; at fixed depth 0.95.

Height-Packed Outline & Zoom-Locked FBO

  • Alpha height packing: Solid geometry writes gl_FragColor.a = 0.58 + clamp(vHeightZ / 76.0, 0.0, 1.0) * 0.41; shadow fragments write 0.44 alpha.
  • Post-pass (POST_FRAG): Samples 4 cardinal neighbors with uTexel. If c.a >= 0.56, detects internal elevation steps (stepH = 0.024) to shade bottom-right rims darker (0.72) or top-left ledges brighter (1.08). Exterior pixels adjacent to solid geometry draw 1-texel dark ink vec3(0.072, 0.066, 0.088); remaining ground shadows render at 0.36 alpha.
  • Zoom invariance (PIXEL_WORLD = 1.0): renderScene() allocates fboW, fboH directly in fixed world texels (capped by maxTexSize and world + 180px padding) and snaps (wx0, wy0) to integer PIXEL_WORLD boundaries to avoid pan shimmer. GameRenderer.renderWorld blits scene.canvas inside the active world camera matrix at (scene.x, scene.y, scene.w, scene.h) with ctx.imageSmoothingEnabled = false.
  • Cameo Portraits: Startup calls renderer3d.bakeAllPortraits(), rendering each of the 16 units + 7 buildable buildings per faction into 78×62 PNG data URLs stored on portrait cards.
  • Biome Rock Tinting (uTint): ENTITY_FRAG multiplies vCol * uTint; rock meshes pass biome.rockTint so boulders shift naturally across Steppe, Desert, Tundra, Ashland, and Marsh without duplicating VBOs.
  • 3D→Pixel Hardware Cursors (bakeMeshIcon + js/cursors.js): Pixel3DRenderer.bakeMeshIcon(parts, opts) renders procedural MeshBuilder cursor meshes (faceted 3D arrowheads via addFacetedDart, reticles, crates, flags, wrenches, and 8-direction scroll chevrons) through the exact same 2-pass WebGL shadow + outline FBO into 32×32 PNG data URLs, then deletes temporary VBOs. FL.CursorSystem injects all 20 --cur-* CSS variables into #ironFrontCursorStyles for zero-latency hardware OS cursor rendering. Edge-pan arrows place their hotspot at the leading tip (e.g. pan_e at 27,16) so the entire arrow stays inside the viewport when grazing screen borders. Inspect all 20 baked cursors & hotspot crosshairs at 3× zoom via index.html?cursors=1.

4. Simulation Architecture, Power & Repair Rules

Core Loop & Match Start (RtsSimulation)

  1. loadMap(rawMap) expands JSON maps via FL.MAPS.expandMap(), updates sim.worldW/worldH, playerSpawn/enemySpawn, and resizes FogOfWar. startNewGame(faction, diff, mapData) spawns HQ-only bases at the map's spawn points (0 units by default, plus optional map.rules scenario overrides); AI expands via relative anchor logic (depot near closest supplies → motorpool → generator → front bunkers, with spiral placement fallback).
  2. Clamp dt = Math.min(0.05, Math.max(0, rawDt)); pause/gameover short-circuits early.
  3. Clear transient frame flags: repairBeams.length = 0, all b.isRepairing = false, all u.isRepairing = false & u.repairKind = null.
  4. Run updateCapturePoints(dt) (data-driven oil outposts from map.capturePoints), updateSupportPowers(dt), updateBuildings(dt), updateUnits(dt), resolveCollisions(), updateProjectiles(dt), cleanupDestroyed(dt), effects.update(dt).
  5. In active matches (!demoMode), add AI passive income, run updateEnemyAi(dt), check win/loss (all enemy/player buildings koTimer<=0 count === 0 triggers 1.2s end delay), and refresh FogOfWar.

Command & Conquer Power Grid Rules

  • recomputePower() iterates living completed buildings only (b.koTimer <= 0 && b.buildProgress >= 1). Placing a building does not alter powerProduced or powerConsumed until construction hits 100%.
  • Construction (b.buildProgress < 1) always runs normally even during Low Power so players can build generator (+50) to recover.
  • When isLowPower(faction) is true (powerConsumed > powerProduced), isBuildingPowered(b) returns false for power consumers motorpool, bunker, heavyGun, workshop, and command:
    • motorpool pauses unit production queues.
    • bunker & heavyGun turrets stop scanning/rotating/firing.
    • workshop stops repairing nearby vehicles.
    • command stops rotating its dish; player artilleryBarrage locks (powered = false) and pauses cooldown recovery.
    • hq, generator, and depot (dropoff & harvester production) stay powered/usable so the economy cannot permanently deadlock. Destroying an enemy building immediately triggers recomputePower() inside applyDamage().

Repair, Salvage & Veterancy

  • Manual Building Repair: Selected damaged buildings toggle b.repairing, healing 36 * dt HP at 0.24 supplies per HP and setting b.isRepairing = true.
  • Field Unit Repair: Powered workshop (radius 195, 30/s) and repair APCs (red_apc_truck r165 / 12/s; green_apc_8x8 r150 / 10/s) heal one damaged ally per frame and flag u.isRepairing = true; u.repairKind = 'field'.
  • Veteran Auto-Repair: Ranks 0..3 unlock at 0 / 1 / 2 / 3 enemy combat-unit kills (last-hit killer receives +1 XP; buildings and unarmed harvesters do not grant rank). Rank 2 grants regen: 6 HP/s and Rank 3 grants regen: 12 HP/s when elapsedTime - u.lastCombatTime >= 5.0, setting u.isRepairing = true; u.repairKind = u.repairKind || 'auto'.
  • Salvage Wrecks: Destroyed combat units drop salvageable wrecks; harvesters automatically collect wrecks within 260 world units before mining supply crates.

7. Extension Playbooks & Known Gotchas

Playbook: Adding a New Unit

  1. Add mesh builder calls producing M.<kind>_hull (and optional _turret, _barrel) inside js/units_meshes.js.
  2. Add stats entry to UNIT_SPECS and append key to FACTION_UNITS.red|green in js/sim.js.
  3. Add draw switch branch in Pixel3DRenderer.enqueueUnit and camera framing tuple [span, midZ] in bakeAllPortraits().unitCfg inside js/renderer3d.js.
  4. Optional: Mirror mesh & catalog metadata inside standalone showcase.html if inspecting it there too.

Playbook: Adding a New Building

  1. Add B.bld_<kind> (front oriented along +X at 0°!) in js/buildings_meshes.js.
  2. Add spec in BUILDING_SPECS & key in BUILD_ORDER in js/sim.js; wire behavior in updateBuildings guarding active systems with if (... && powered).
  3. Add optional rotating head/turret logic in enqueueBuilding and entry in bakeAllPortraits().bldCfg inside js/renderer3d.js.

Playbook: Creating a New Map (AI Agent & Human Workflow)

  1. Create a declarative JSON file in maps/<slug>.json using schemaVersion: 1. Supported biomes: steppe, desert, tundra, ashland, marsh. Sizes: w ∈ [1200, 4800], h ∈ [1000, 3600].
  2. Compact AI shortcut (autoMirror): Set "symmetry": "point" | "x" | "y" and "autoMirror": true, then define ONLY the player's half (1 player spawn, supplies, roads, obstacles, outposts). FL.MAPS.expandMap() mirrors everything automatically (skipping objects on the exact symmetry axis/center) and flips enemy HQ facing.
  3. Add the filename to maps/manifest.json and run node scripts/validate_maps.mjs --sync-builtin to verify clearances, HQ build slots, economy balance, and 48px BFS reachability — and update the offline fallback js/maps_builtin.js.
  4. Visual polish (Human): Open editor.html?map=<id> to tweak rocks/roads/pads visually, verify live validator badges, click Тест-бой ▶ (launches index.html?map=draft), or exchange JSON via the JSON modal.

Playbook: Adding or Tuning a 3D→Pixel Cursor

  1. Add a procedural 3D mesh builder in js/cursors.js (use addFacetedDart or MeshBuilder primitives; keep top-face quad winding counter-clockwise so normals point +Z toward the sky light).
  2. Register it in CursorSystem.bakeAll() with exact pixel hotspot (hx, hy) inside [0..31] (tip hotspots for pointers and edge-pan arrows; 16,16 for centered reticles).
  3. Wire its condition in resolveGameCursor() (guarding enemy/supply checks with fog.isVisible / fog.isExplored!) or syncEditorCursor() in js/editor.js.
